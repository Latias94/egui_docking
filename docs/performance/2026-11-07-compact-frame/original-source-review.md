The pending transition is equivalent to the old saved-size Option (candidate layout.rs:1091-1143). Entering child k first reads its solved extent and successfully constructs its rectangle. Only then does it increment next_child to k+1, set pending_child, and push the parent continuation below the child's Enter frame. The child's complete DFS executes before the parent resumes. The pending branch clears the flag, reads `child_range.start + next_child - 1`, adds that exact extent once, optionally constructs/stores the following parent gap, adds the original thickness, and schedules another continuation. That following continuation has no pending child, so it cannot add the same extent twice. A true flag implies a preceding increment; subtraction cannot underflow. The last child still contributes its size without an extra gap, and zero-child raw input follows the previous completion path.

Rereading the solved extent is safe under both supported topology construction paths. Runtime RootStructure allocates each split's complete child range before descending. The raw compiler allocates separate ranges when each split completes. Distinct rows therefore have disjoint actual-output subranges, and the slab's min/max/actual segments are themselves disjoint. An active parent cannot be revisited as a descendant without a cycle. The checked raw compiler explicitly rejects an active-row revisit while allowing only already-completed rows to be reused. During this DFS there is no second active branch that can re-solve the pending ancestor's range. Its reread returns the original stored f64 value; no solve, conversion or inverse geometry is repeated.

Completed raw DAG reuse remains supported. Repeated visits may overwrite the already-completed row's own NodeResult and split segment, just as the base did. They cannot overwrite an active ancestor's row or segment in an acyclic graph. First visits follow the same child order as row issuance, and revisits use already recorded rows, so NodeMap::record and the new read never require an uninitialized hole. The preserved `completed_subtree_reuse_keeps_active_cycle_and_leaf_error_order` compares both valid reuse and cycle/missing-leaf outcomes against the independent reference. This patch neither strengthens raw DAG input into a tree assumption nor suppresses the raw compiler's diagnostics.

The bounds reader is an appropriately private facet, not new authority (projection.rs:44-47). A continuation can only be created after prepare recorded that exact row's NodeResult (layout.rs:965-971). The new accessor copies the same LogicalRect that used to live in the frame. Immutable topology supplies axis, child range and splitter range; no Workspace reference, current root issuance, new leaf answer or successor geometry is requested. The defensive Split-kind branch names the immutable row that produced the continuation and is unreachable as an error for these construction paths. It adds no reachable public validation/error priority. Cardinality fallback and geometry errors remain Results at their original semantic points.

The exact original thickness is preserved. prepare still calls the unchanged projected_splitter_geometry once, passes its splitter extent to the original solver, and stores its returned splitter_thickness in the continuation. advance uses that stored scalar.
