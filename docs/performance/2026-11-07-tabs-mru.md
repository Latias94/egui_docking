# Give each Tabs node its own complete history

Move the MRU Vec into `Node::Tabs { items, selected, mru }` and delete the
separate `TabMruStore`, its BTreeMap, Arc payloads and maintenance joins.
The existing `NodeStore` COW channel now owns the complete Tabs value.
`Workspace::tab_mru` remains a borrowed lookup. Explicit enum literals and
exhaustive patterns must adopt the new field; constructors retain their initial
selected-first history. These are raw implementation interfaces: `graph` is
private in the delivered crate. The product model/runtime facade stays the
external integration boundary.

Builder replacement installs and returns a complete Node including its explicit
history. Snapshot schema/version, mandatory serialized MRU and strict malformed
permutation checks remain. Only diagnostics for impossible detached MRU storage
are removed. Actual selection, transfer, empty-central merge, canonicalization,
staged failure, exact root issuance and old-output ownership keep their existing
semantics. A three-item staged selection roundtrip additionally verifies that
unchanged final selected/visual order with changed MRU is still reported as a
real durable change, preserves the original Workspace and rejects its old ref.

Workspace candidate copies no longer clone an MRU map or one MRU Arc handle per
Tabs. They still fork the node arena, placement and other metadata. The Vec data
remains real storage. COW now copies the complete Node: visual-only Reorder can
copy unchanged history, and a history-only Builder edit can copy visual items.
The public enum's allocation size can change for both variants. These are
tradeoffs, not zero-copy or allocation-byte claims.

Ordinary work accounting deletes the three counters for removed MRU owners and
retains actual `mru_item_copies` in `Node::clone`. Its 20-column work CSV retains
the successful RootStructure counters. The formal timing schema, fresh leaf
collection, complete owned exporter and every timer boundary remain unchanged.

The rebased reviewed patch is SHA-256
`9046e9d14bb92bdb7aab2e8935b08aa3f4f5849f135e1b0edef595f50f216c01`,
against the exact RootStructure + single NodeResult source. All 24 input/output
hashes match at application. Independent review verifies the original 85 MRU
hunks, the two NodeResult context adaptations and the new history-only witness.

2,068 production core, 2,244 workspace, four no-default public integrations and
292/335 public host cases. The three opt-in probes remain skipped in ordinary
suites. Formatting, correctness/suspicious Clippy, strict docs, doctests and
dependency checks pass. The ordinary 21-cell work probe has the expected 20
columns; actual MRU entries copied are four per center/cross-view move, two per
edge and zero per resize. Successful root-body counts remain unchanged. These
are logical copy events, not allocator-byte or latency measurements.
