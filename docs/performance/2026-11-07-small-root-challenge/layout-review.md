**Finding: the remaining fourteen small cells are a real unmet target, not evidence of an architectural latency floor or a general overvalidation diagnosis. One further bounded candidate is justified: keep the existing slice composers, but gather binary measurement children into a two-record local array instead of the temporary Vec.** This addresses a concrete owner in both one-view and four-view projections without another solver, dependency, persistent cache or generic container.

**The common boundary is substantial, but the products perform different additional work.** Rust's timer includes request capture, actual transaction application, fresh leaf-answer gathering and all-root measurement/projection, followed by a fresh complete common-word export (`docking_cost.rs:441–468`). Its projection/report/export owners survive the final timestamp. The leaf reader consumes freshly gathered `(NodeId, Constraints)` records with identity matching; it is not a constant-return callback (`197–256`).

The C++ timer likewise captures a real request, executes `DockContextProcessDock`, updates every root, lays out every root and constructs an owned common-word vector (`imgui_docking_cost.cpp:282–355`). The upstream routines are not empty substitutes: `imgui.cpp:19260–19334` recursively updates flags, checks windows for removal/collapse and updates visibility; `19376–19411` refreshes root information; `20615–20708` assigns child rectangles recursively. The no-central fixture also makes `DockNodeFindInfo` traverse without its central-found early exit (`19227–19246`). Omitting those scans from an explanation would understate ImGui's timed work.

ImGui updates existing node/window state in place. Its size allocator handles two child pointers, minimum spacing and size ratios; the fixture sets `WindowMinSize` to zero. Rust additionally composes explicit subtree minima/maxima, executes its general constrained allocator, and stores node rectangles/constraints plus every parent-edge minimum, maximum, actual extent and following gap, central choice and overflow/unallocated outcome. These are three fresh result buffers per root, already consolidated (`layout/projection.rs:25–33,165–220`). The common export contains rectangles, structure, item order and selection intent; it does not exhaust those richer outputs.

Rust also prepares an independent candidate from `&Workspace` (`operation.rs:628–700`), preserving staged failure/discard, retained originals, MRU and stale identity semantics. ImGui's timed live mutation does not provide that separate publication contract (`imgui.cpp:18697–18833`). Those differences explain scope; they neither excuse missing the target nor prove the implementation is minimal. Renderer, native host and GPU work are absent from this comparison.

**“Overvalidation” needs an exact boundary.** Committed projection already borrows completed RootStructure rather than rebuilding a checked graph (`layout.rs:484–520`). Some durable axis checks can be redundant under that closed invariant; the queued axis treatment tests precisely that proposition. Other checks remain necessary: finite rectangle corners can produce an infinite subtracted extent (`geometry.rs:215–222`), and finite child constraints can overflow an aggregate (`layout.rs:832–896,1434–1443`). Public numeric input, selected overrides, checked raw diagnostics and earlier geometry errors retain their contracts. The restricted balanced, binary, inactive-constraint fixture does not justify weakening them globally.

**Recommended additional experiment: binary measurement gathering with the original composers.** `layout/topology.rs:146–175` creates one `child_values` Vec per measurement, clears it for each split, copies child constraints into SubtreeMeasurement records, then borrows its slice. For exactly two child rows, construct those same two records locally and call the unchanged `compose_constraints` with their slice. Keep the original clear/extend Vec path for every other arity. No public interface or arithmetic specialization is needed.

Apply the same storage choice at the existing delayed-maximum gather (`layout.rs:607–636`), only when that pass actually runs. Do not eagerly compute maximums during minimum-only measurement or discard. Preserve child order, minimum-before-maximum folds, checked-sum labels, splitter-thickness evaluation and Constraints construction. The independently checked raw compiler and reference oracle can remain byte-identical; projection traversal, raw repeated-parent/last-write behavior and central routing need no changes.

For a fully binary root this removes the measurement gather's populated heap owner, not one allocation per split: the original Vec is already reused. The two records still copy the same constraints and are genuinely materialized. General-arity storage, fresh Adapter answers, all three final output buffers and complete export remain. The change requires only the two gathering sites and uses ordinary local arrays borrowed by existing slice functions.

This differs from rejected childrows, which changed the composer interface/iteration, and from rejected SmallVec, which changed the continuation container and reserved sixteen frame slots. Neither rejection proves this smaller representation wins. Its new arity branch, local-record footprint and compiler effects can still regress; the compiler may already optimize some original overhead. No allocation-time fraction or speedup follows from this inventory.

**The goal remains active.** Fused continuation, numeric hint, axis-inline, exact-assigned and persistent-directory variants still need their own complete measured retention decisions; none is counted as a win here. The proposed measurement slice is another falsifiable owner deletion, not a substitute for that queue or a promise to close all fourteen cells.
