# State ownership and invalidation architecture review

Date: 2026-11-06. Source baseline: `54840717a2454c957b13a667a939ddf8229e52e9`.

This lane read current source, the linked-targets, title-resources, and compiled-finalization reports, and the root agent's fresh idle sample. It made no repository changes and ran no builds, tests, benchmarks, or network requests. Source references below are relative to the repository root. Rankings concern the potential scope of work eliminated, not measured milliseconds or a promise to close the complete ImGui product gap.

The strongest current architecture issue is loss of dependency locality. A selection changes one `selected` field and one stack's MRU, but the publication interface communicates a new whole-workspace snapshot and a new semantic requirement identity. Consumers then reconstruct much more than the actual changed facts. This is real amplification. It does not establish that the numerical layout solver or Rust ownership accounts for most of the remaining product gap. The fresh sampling communicated by the root agent puts requirement refresh around 2.7%, compiler around 10%, validator around 4.5%, and the standalone solver around 0.8% of sampled click execution; these categories overlap and include work outside the timed interval. A state-only rewrite has no evidence-based claim to recover the full product ratio.

## Ranked current causes

### 1. Semantic authority identity is also the invalidation boundary for structural presentation products

**Direct evidence.** A root fingerprint combines topology, owner, selected items, and MRU. Surface semantic snapshots contain these full fingerprints. Requirement refresh detects any change at that granularity and rebuilds the whole draft/index inventory, then invalidates the changed surface's complete Ready plan. The source references are steps 2 and 6–8 above. This is a local-to-whole-surface fanout even when the selected tabs share equal measured minima and the effective tab policy is unchanged. There is also whole-workspace derivation work across otherwise unaffected surfaces, despite correct per-surface invalidation.

**Necessary semantics.** The exact old source proof, selected pane policy, MRU behavior, pending native saga barrier, output authority, and selected minima must remain correct. Selection can alter the selected-pane minimum and pane-local policy; `workspace.rs:653–663` derives a pane-local target rule from the selected item. Geometry cannot universally be reused from topology alone.

**Implementation choice.** The complete structural measurement roster is not generally a function of selection: current requirement derivation already asks for minima for every tab item (`scene_compiler/requirements.rs:151–161`) and intrinsic measurements for all eligible tabs (`:198–214`). Traversing every unrelated node to regenerate this roster and binding a new complete scene are choices of the present module interface, not an inherent requirement of MRU or atomic publication. Full source proof freshness and geometry dependency freshness need different consumers.

**Plausible scale and unknowns.** The avoided work could include requirement/index traversal and reconstruction of unchanged scene views. Proof materialization is at least proportional to the root representation it snapshots; requirement derivation additionally pays ordered-map/set construction costs. The remaining compiler/validator/adapter/output work is not accounted for by those costs. No measured bound exists here for a partial compiler, and equal layout does not guarantee equal hit/semantic/program records.

### 2. The rollback unit is much larger than the domain mutation

**Direct evidence.** `Workspace` owns one `SlotMap<NodeId, Node>` plus all roots, surfaces, floatings, and MRU maps (`graph.rs:356–363`). `Node` owns item/child/weight vectors (`:165–182`). A one-tab selection clones that complete owned value before changing its small local state. Its report infers change by comparing complete workspace values. Transient strip reconciliation similarly copies the full store and every live roster, although selection does not alter item membership (`tab_strip.rs:603–646`). The host-frame candidate/checkpoint additionally clone those owned stores on idle.

**Necessary semantics.** Failed commands, failed presentation admission, dropped prepared frames, and discarded encoding passes must leave the published workspace unchanged. MRU updates must be atomic with selection. Those obligations require isolated mutation; they do not require copying unrelated visual-item vectors and root records for every selection.

**Implementation choice.** Durable topology and selected/MRU runtime state currently share the same arena publication unit. Complete cloning is a simple implementation of rollback. A change summary is not retained in `PreparedTransaction`, so later consumers rediscover what changed by comparing large values.

**Plausible scale and unknowns.** A successful or rejected local select can pay whole-workspace allocation/copy costs. An unchanged selection can still clone and recapture proofs before reporting no change. Large public batches or a single-root layout limit the value of root-only copy-on-write: changing one tab in a large single root would still copy that root. Current attribution does not establish clone cost as a dominant latency term. Do not begin with a generic persistent graph rewrite on this evidence alone.

### 3. Value equality is used as a change-detection protocol over immutable shared products

**Direct evidence.** The actual fresh idle stack is `CoreHostPresentationFrame::prepare_owned -> DockEngine::reduce_tick_candidate -> SurfaceSceneSet::eq -> SurfacePlanScene::eq -> PresentationPlan::eq / HitGeometry::eq` (root sample lines 1545–1568 and 1640–1641). The caller is `engine/reducer.rs:938`; it is not `install_ready`. `SurfacePlanScene` owns Arc-backed plan/hit/program/semantic products (`scene/lifecycle.rs:119–126`), while `PresentationPlan` contains every presentation record inventory (`scene.rs:208–236`) and `HitGeometry::eq` compares whole region arrays (`presentation_hit/geometry_reuse.rs:20–23`).

The existing `PresentationAuthorityState::eq` also compares its scene by value (`engine/presentation_authority.rs:36–75`), but this lane did not find it as the hot production caller in the fresh sample. Its existence should not be conflated with the actual reducer comparison.

`Arc<T>::PartialEq` does not automatically turn arbitrary `T: PartialEq` into identity comparison. The local Rust 1.95.0 standard-library source (`.../library/alloc/src/sync.rs:3504–3532`) has a default dereferenced value comparison and an identity shortcut for the reflexive `MarkerEq` specialization. These floating-point-rich presentation types implement `PartialEq`, not `Eq`. Thus sharing avoids copies but does not remove these scans. The observed fresh sample confirms that distinction for this binary.

**Necessary semantics.** `published_state_changed` must correctly report scene state changes, including candidate/fallback/interaction authority distinctions. Value equality remains useful for independent plans and testing. Replacing `PartialEq` with unconditional pointer identity or declaring floating-point types `Eq` would change semantics incorrectly.

**Implementation choice.** The production change detector can consume mutation outcomes or a sealed compact authority comparison. The existing `surface_scene_deltas` already compares compact authority tuples; those tuples may need extra fields for all `published_state_changed` distinctions, so they are a starting point, not proven complete. A dedicated same-published-state method can explicitly short-circuit identical immutable owners and compare small authority fields without redefining public value equality.

**Plausible scale and unknowns.** This adds scans proportional to retained scene/hit products on stable idle. The root agent's final attribution measures the entire `SurfaceSceneSet::eq` inclusive subtree at **4.288% for idle and 2.887% for click**. Earlier figures around 1–2% covered only partial `HitGeometry`/`LayoutFacts` leaf categories; they were not the complete equality subtree. The new inclusive scope makes this a worthwhile bounded experiment, but these sampled proportions include execution outside the timed frame and do not establish exact frame budgets or savings. This remains a lower-risk seam, not an explanation of the entire idle gap.

The exact comparison hierarchy is `SurfaceSceneSet { surfaces, revision_tombstones, popup_requirement }` (`scene/lifecycle.rs:711–716`) -> `SurfaceSceneRecord { scene, native_first_live }` (`:682–686`) -> `SurfaceScene` (`:429–436`) -> Ready/Stale slot fields (`:102–126`, `:373–379`) -> Arc-backed immutable products. The separate delta path compares only `(stamp, kind, interaction_authority)`. Reusing that public delta vector alone for `published_state_changed` is therefore not proved equivalent: fallback, confirmation, native-first-live provenance, popup, and revision-frontier differences also participate in today's full equality.

A concrete journal design is for `SurfaceSceneSet`'s mutation methods to return/retain an ephemeral change record, with the initial compact slot identity for each touched surface and global popup/frontier changes. At finish, compare initial/final compact identities for touched surfaces, generating the existing public authority deltas from that same pass. Include candidate/fallback output identity, confirmation and interaction authority, coordinates/native-first-live binding, and global fields where today's change semantics require them. A boolean OR over mutations is insufficient when later edits restore the original state. The journal must cover observation, manifest reconciliation, install/demotion, native binding, retirement, and encoding restart; `changed_contribution_surfaces` covers only one part of this lifecycle. The owner should record actual transitions, not incidental remove/reinsert operations in a map. This is a change in publication protocol, not a cache or a new cross-frame invalidation map. A pointer short-circuit is a smaller first experiment while this coverage is established.

## Preferred architecture seam

Introduce a compiler-owned separation between the structural presentation input inventory and the current semantic/output binding. Keep public workspace versions, command proofs, native barriers, exact measurement answers, and the complete output audit.

1. The workspace transaction owner should produce a small internal mutation description: selection/MRU at a tabs node, item/order/ownership/topology changes, changed roots/surfaces, or conservative unknown. This information comes from the operations that already perform the edits; it must not be inferred by a second general validator. Batch semantics must account for changes canceled by later commands rather than blindly OR-ing every command's `changed` flag. Untrusted draft/public-import routes retain the conservative path.
2. Give the requirement owner an immutable structural inventory that can survive selection. A selection reevaluates effective selected-pane policy/minimum dependencies for its actual scope; unchanged inventories stay shared. Keep one published manifest owner, rather than adding parallel global generation maps whose consistency must be proven independently. Structural commands still rebuild the affected inventory, and initial validation remains authoritative.
3. Let the scene compiler consume the changed-node description and previous sealed facts. Reuse only geometry/chrome chunks whose actual measurements, selected minima, effective policy, coordinates, resize inputs, popup/contained ordering, and topology match. Rebind the new semantic/output authority even when geometry survives. Full root fingerprints can be captured once per new root state and used for current command binding; old output must not acquire current-input authority merely because its geometry survived.
4. Make published-state change a result of mutation/publication operations, with an explicit immutable-owner equivalence fallback. Keep `PartialEq` as value equality for arbitrary independent objects. This avoids using an expensive equivalence query to discover what the owner already knows it did.

This seam deletes complete structural roster derivation for selection, reconstruction of unaffected presentation chunks, and stable shared-scene value scans from the production change protocol. It does **not** delete source validation for arbitrary public commands, fresh measurement callbacks, changed selected-pane minima/policy handling, native source freezes, final output verification, or atomic frame publication. Extra state is the immutable structural inventory/chunk ownership and an ephemeral mutation summary. The main risks are incomplete dependency classification, stale target-policy binding, discarded-pass/rollback frontiers, and a hidden consumer that treats a complete surface ticket as the only legal cache lifetime. The first implementation should cover one local selection case and conservatively fall back for every unhandled operation.

This is preferable to immediately redesigning all graph ownership: it attacks the work amplification at the current presentation boundary and can be measured before a persistent arena is justified.

## Alternative: transaction storage redesign first

Separate immutable node structure (items, split children/weights, ownership) from selected/MRU state, and stage local selection as a small patch against a sealed snapshot. A bounded chunked table or a narrow copy-on-write tab-state store can make the isolated update local; a root-only clone cannot guarantee this for a large single root. Expose internal snapshot-bound selection authority so a current-frame action need not materialize and then verify the same root proof twice; preserve the public full-value proof route and its current ABA/value-equality behavior.

This removes selection's complete topology clone and duplicate current-source capture/check, and can reduce transient roster copies. It does not by itself stop whole requirement/index/scene rebuilding. Additional graph storage, overlay reads or chunk ownership, public serialization behavior, batch normalization, and old snapshot lifetime make it riskier than the preferred seam. Replacing full proofs with only monotonic revisions would change which independently constructed or restored states compare equal; that change must not be smuggled into a performance patch.

## What should remain

- Keep the preserving-selection postcondition and its general fallback; do not reintroduce general canonicalization into the selection path.
- Keep exact workspace-owner provenance for index reuse and the old-layout topology guard. They prevent reusing facts from another workspace or falsely accepting old geometry authority. The new design should add a narrower valid dependency, not weaken their checks.
- Keep the full pending native source semantics at `engine.rs:4210–4219`, MRU behavior, presentation/output tickets, and dropped-frame rollback. A local fast path may produce the same semantics through owner-minted capabilities.
- Keep the current Arc sharing and compiler-owned finalization gains. Arc is useful storage ownership; its ordinary `PartialEq` is simply a different operation from identity/change detection.
- Do not replace every ordered map, remove all validators, or rewrite the forest arena based on product ImGui ratios. The current evidence supports a targeted dependency/interface change followed by measurement, and a smaller idle equality cleanup; it does not support a new proof framework or a wholesale engine rewrite as an established latency win.

## Cross-examination of the scene lane

### A generation container is insufficient

The scene lane correctly acknowledges that `SurfacePlanScene` already owns the plan, hit view, paint links, semantic view, and coordinates together (`scene/lifecycle.rs:119–126`). Merely placing those fields in another `Arc<CompiledSurfaceGeneration>` changes neither the selection invalidation nor the work at installation. In particular, `install_ready` still builds hit/semantic views at `:1264–1270`; ordinary paint helpers still perform semantic-ID joins; new measurement answers still pass through keyed-map exact-set processing. Calling this existing aggregate a generation is not an optimization by itself.

The proposed generation is valuable only if it changes specific dependencies/protocols: (1) receiver association becomes a checked private row relation established once, (2) synchronous measurement answers remain bound to the core-issued request rows instead of reconstructing their key relation, (3) immutable fact lifetime is independent from fresh output binding, and (4) selection is allowed to retain explicitly unaffected fact chunks. Current hit and semantic manifests embed an output ticket (`presentation_hit.rs:417–420`, `semantic_manifest.rs:19–22`), while plan targets embed current command facts. A generation that retains all those bindings has to be replaced on semantic/output changes anyway. The important split is reusable facts versus current authority, not a new container name or another global generation counter. The existing types can implement these seams incrementally; a bulk container migration is not a demonstrated prerequisite.

### A bounded selection-only contract for structural inventory reuse

Start with **exactly one successful `WorkspaceCommand::Select`** on an eligible canonical snapshot and an ordinary tiled tabs node. Keep the conservative path for batches, structural commands, contained raise-plus-select, active popup, resize/drag interaction, recovery, and any pending native create/rehome. Stable config, policy revision, coordinates, ownership, item/order and split facts are required. This handles a useful real click path without a generic dependency graph.

- **Effective policy:** recompute the changed bar's policy using its *new selected-item rule*. Frozen policy evaluation is explicitly an intersection of workspace/surface/target rules (`policy.rs:1434–1447`); unchanged policy revision alone does not imply unchanged bar policy. Compare the resulting complete effective policy with the old bar requirement. If it changes, initially fall back. At a stable policy revision and item roster, item close capabilities remain the same (`:1454–1463`). Other bars' requests do not change.
- **Complete Q:** if the effective policy is unchanged, the complete pane-minimum, intrinsic, and strip key inventories remain reusable; copy/share their identity and bind a fresh requirement ticket as needed. Continue calling the resolver for every current key and preserve answer/unavailable/error behavior. Every item minimum is required for drag projection (`scene_manifest.rs:184–189`), not just current selection. Inventory reuse is not measurement-value reuse.
- **Selection and geometry:** after fresh complete measurement answers, compare the *old selected item's and new selected item's actual effective leaf minimum*, including the bar contribution (`scene_compiler/surface.rs:2024–2048`). Equal minima and policy are necessary but not sufficient for chrome reuse: selection can reveal a previously clipped tab and change scroll (`:1297–1313`). Initially rebuild the changed bar's chrome/selection/program/semantic facts and retain only independently proved unaffected chunks; use the conservative compiler if the selected minimum changes. Do not label unchanged topology as unchanged geometry.
- **MRU and full source:** continue the exact MRU permutation update and publish the new full semantic root proof. The layout/requirement reuse decision must not substitute an old fingerprint for that new proof. Current public stale-source equality and pending source preservation remain unchanged. Reusable geometry can reference structural rows, while command binding supplies the current proof/rule; otherwise embedding old proof-bearing targets defeats the intended separation.
- **Native freeze:** retain `first_pending_presentation_source_mismatch` (`engine.rs:4181–4221`) unchanged. The initial optimization rejects its own eligibility whenever native/rehome/recovery state is pending and uses today's full path, rather than attempting to infer that selection is harmless to a frozen native source. Extend eligibility only in a later measured change with explicit lifecycle evidence.

This pilot requires a small owner-issued selection mutation description and one explicit eligibility predicate. It does not require general command dependency inference, a DAG, Merkle proofs, or a second validation framework. Returning to the existing conservative path is a correctness mechanism for unsupported cases, not an invitation to silently reduce Q or skip current measurement callbacks.

### Priority by end-to-end opportunity, not ease or confidence

The scene report ranks equality first by confidence/actionability; that must not become the performance roadmap. The broad opportunity for **selection** is stopping local changes from requesting whole structural and derived-view reconstruction. Requirement refresh alone is only about 2.7% of the fresh click sample; it is a prerequisite seam, not the expected total win. A pilot should measure requirement work *and* downstream compiled records/views before expanding.

For **every-frame idle work**, row-bound measurement and ordinary receiver links are separate high-value experiments: the fresh sample shows measurement/resources and receiver work at larger inclusive scopes than equality, although only some work in either category is removable. The root agent separately classifies measurement-map insertion at **3.228% for idle and 2.165% for click**. That is positive attribution for the keyed conversion, not a forecast that a row-bound batch saves that entire share. These changes can be implemented in the current aggregate without waiting for a wholesale generation refactor. Full output-audit work also remains a separate target; sharing a generation does not automatically remove it.

The final 4.288% idle / 2.887% click inclusive scene-equality category justifies a bounded change-detection experiment, not a new generation architecture on its own and not repeated equality-only rounds ahead of invalidation/association work. The earlier 1–2% leaf observations must not be presented as the entire equality cost. Full transactional storage redesign ranks after direct clone attribution. None of these category sizes is an additive savings forecast, an exact timed-frame budget, or an ImGui core ratio.
