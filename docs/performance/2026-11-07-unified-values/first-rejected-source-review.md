I found no supported-input contradiction in the remaining central-chain, raw-DAG, numeric/error-order or ownership paths. The central Vec is semantically coherent for committed trees but adds avoidable storage and lookup complexity; the scalar frontier suggested by the separate design review is a useful smaller alternative. This report is source review only, not compilation, executed behavior, qualification or a performance result.

The required correction is at candidate layout.rs:937-948 and projection.rs:96-99. In the parent, NodeMap::record appends only at row == values.len(); otherwise it indexes values[row]. An earlier row is a valid overwrite, but row > length fails through Vec indexing in both debug and release. In this candidate, values is already N elements long. The separate visited_prefix and its row <= prefix check exist only under cfg(debug_assertions). Therefore a valid in-range row that jumps over an unvisited prefix is accepted in release, and no longer has the parent's defensive rejection. This is the exact behavior the earlier design review required preserving. It is not evidence that a currently supported owner-built tree can generate such a jump.

The minimal repair is local: retain a scalar first-visit prefix in every build, reject row > prefix on every Enter with a non-debug assertion/invariant check, increment at equality, and permit earlier-row revisits. The final complete-prefix check may retain the parent's debug-only strength. No N-element visit flags, new error validator, graph metadata or traversal framework is needed. This review did not alter the candidate or demand a test mirroring a private helper. The existing body-built first-visit ordering justifies the assertion; prefilling storage cannot replace it.

The production central chain is otherwise sound under the declared committed-tree invariant (topology.rs:150-186). It seeds only at a matching Tabs row after that leaf's original constraint read succeeds. A Split ID, absent ID or stale generation cannot seed it. In postorder, unrelated branches cannot contain the current tip as a direct child of a tree; they leave it untouched. The next actual ancestor promotes it after its own composition succeeds. Ancestor preorder rows strictly decrease, so reversing the accumulated list yields the sorted set required by binary_search. The final tip is row zero exactly when the requested central leaf was reached. Central-root Tabs, central None and first/middle/last branch positions follow the original semantics. Reachability rejection remains after all measurements, preserving earlier leaf/composition failures.

Projection's ordered position still selects the first direct child whose subtree contains central. The list contains exactly the central leaf and ancestors, so binary search reproduces the former per-row boolean test. Central None leaves an unallocated empty Vec and skips the lookup. However, this is not a constant-cost substitution: for H central ancestors, the list grows/reverses in O(H) space/work, and child membership costs O(log H) instead of a boolean read. Across the committed tree, central classification during geometry is O(N log H) in the worst case; the existing 10,000-deep central spine can have H = O(N). Production measurement itself remains O(N), because its direct-roster contains scans total at most the tree's edges. There is no new recursive call stack.

The scalar alternative in `/tmp/unified-measurement-results-review.md` (SHA-256 `8c3a71f9789a45a3a63fc240b14dad9ef9cf2b83aa128e7f3e4350b13137e334`) avoids those production costs without new topology metadata. Retain only a central_leaf_row seeded at the same successful Tabs read. During geometry, one local next_central_row begins at root when central exists. Only at that frontier split choose the last direct-child preorder start <= central_leaf_row, then advance the frontier to that child; unrelated branches leave it unchanged. Contiguous committed child subtrees and the known-containing frontier make that predecessor choice valid. Clear it at the central leaf. Total selection work can be bounded by the central ancestors' direct children, at most all edges, with no production central Vec/reversal. This is a source simplification recommendation, not an implemented or measured alternative. It must retain a separate raw membership path rather than applying the tree argument to DAGs.

Minimum-only/discard incurs real unnecessary rect work relative to its own result. topology.rs:145-149 now initializes a zero rect in every NodeResult and RootMeasurement carries those rects while actual bounds are unknown. The contained scene path measures minima at scene_compiler/surface.rs:172-175, then can continue after clipping at :177-178 and drop the measurement without projection. That path never consumes these rects and receives no later unified-output-buffer saving. Full projection also initializes rects before overwriting them. Both old and new measurement initialization are O(N); the candidate increases the initialized record's field inventory and can add an O(H) chain, rather than introducing a new superlinear minimum pass. The arrays remain heap Vecs, with only a fixed-size seed value on the call stack.
